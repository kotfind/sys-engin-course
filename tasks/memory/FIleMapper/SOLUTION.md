# Идея решения

## Алгоритмическая часть

- Т.к. операция `mmap` явно медленнее, чем простое обращение к адресу в памяти,
    то хочется минимизировать количество его вызовов.

- Соответственно, хочется алгоритм сортировки с хорошей пространственной
    локальностью. Я решил взять QuickSort с разбиением Хоара: на основном шаге
    алгоритма (разбиении) оба указателя "прыгают" ровно по одному элементу.
    См. файл `sorter/sort.cpp`.

- Для получения данных из файла, используется алгоритм "буферизации" через `mmap`.

    Имеется ограниченное количество `mmap`-регионов (см. класс
    `UInt64FileRegion`). Если требуемый адрес содержится в одном из регионов,
    то происходит непосредственное обращение к нему; иначе программа `mmap`-ит
    необходимый регион, заменяя им тот, что НЕ использовался дольше всего (см.
    метод `UInt64File::operator[]`).

- В качестве количества буферов выбрано число четыре:

    - два для работы двух указателей (по одному с каждого из концов сортируемого
      интервала);

    - ещё два на всякий случай (например, при обращении к соседним ячейкам при
      переходе через границу буфера).

## Техническая часть

- Так как `mmap` требует, чтобы `offset` был выровнен по размеру страницы, то
  описанный выше алгоритм будет работать только начиная с некоторого
  фиксированного количества `mmap`-памяти (см. метод
  `UInt64File::get_min_mmap_size_limit()`).

- Если заданный лимит `mmap`-памяти ниже допустимого значения, то будет
  сортировка будет выполнена `in-memory`.
